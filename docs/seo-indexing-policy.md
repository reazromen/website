# SEO indexing policy

This policy governs the static pages generated by `cms/build_content.py`. It is designed to preserve useful content and stable URLs while keeping sitemap entries aligned with the page's actual canonical and robots directives.

| URL class | Intended policy | Rationale |
| --- | --- | --- |
| Homepage, about, portfolio, telecom, research and other substantive landing pages | Indexable; one absolute self-canonical URL; included in sitemap | These are intentional search landing pages. |
| Substantive published articles | Indexable; one absolute self-canonical URL; included in sitemap | Preserve article URLs and unique content. |
| Useful topic pages and tag pages with at least three associated published articles | Indexable; self-canonical; included in sitemap | These pages provide a useful cross-article route into the archive. |
| Tag or topic pages with fewer than three associated published articles and no authored description/body | `noindex,follow`; page remains available; excluded from sitemap | They are automatically generated, low-information navigation endpoints. This rule is based on actual taxonomy coverage, not a blanket taxonomy ban. Adding substantive editorial content or reaching three associated articles makes the page eligible for indexing again. |
| `/search.html` | `noindex,follow`; excluded from sitemap | This is a site-search utility rather than a standalone organic landing page. |
| `/posts/test.html` | `noindex,follow`; source content and URL remain available | The page title is `test` and its body is placeholder text (`qswwqs`); it is not a useful search result, but this remediation does not delete the content or change its URL. |
| `/index.html` and nested `index.html` aliases with a verified equivalent `.html` destination | Canonicalize to the verified preferred URL; exclude the alias from sitemap | Keep legacy access while advertising only the preferred canonical URL. Do not redirect nested pages without a verified equivalent. |
| Redirect/alias outputs | Canonical target only; omit redirecting alias from sitemap | Sitemap entries must resolve to indexable canonical content, not aliases. |
| RSS, Atom, JSON feeds and internal search assets | Not sitemap landing pages | These are distribution or utility resources, not HTML search landing pages. |

`robots.txt` permits crawling of public content and advertises `https://reazromen.com/sitemap.xml`. It must not block Google from fetching pages to observe canonical or `noindex` directives. The generated sitemap includes a URL only when its HTML has exactly one self-consistent canonical and no `noindex` directive. Regression tests enforce these invariants.

The historical Search Console count of URLs excluded by `noindex` cannot be fully attributed from repository source alone. The current source audit found no site-wide public `noindex` rule; the old Cloudflare Pages worker contains `X-Robots-Tag` directives but is not packaged into the current GitHub Pages artifact. Exact Search Console examples are still required to classify legacy or externally discovered URLs.
